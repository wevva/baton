# 바통 보안 설계와 점검 결과

> 기준: OWASP MASVS(모바일 앱 보안 검증 표준) 범주 + 차량 앱 특유의 위험. 점검일 2026-11-04, 대상 v0.1 (Pleos Connect 에뮬레이터 v2.1.0).

## 1. 바통이 지키는 것과 위협

| 자산 | 왜 중요한가 |
|---|---|
| 차량 안전 | 앱이 차량 동작에 영향을 주면 안 된다 |
| 인계 기록 | 차내 상태 기록은 사람의 행동 흔적이다 (언제 주차·탑승했는지). 카셰어링에서는 분쟁 증거가 된다 |
| 운전자 프라이버시 | 위치·신원·습관이 새면 감시 도구가 된다 |

| 위협 | 경로 |
|---|---|
| 차량 조작 시도 | 앱 권한·코드를 거쳐 창문·도어·구동계를 조작하려는 시도 |
| 기록 열람·위조 | 기기 탈취, 루팅, 백업·기기 이전, 다른 앱 |
| 정보 유출 | 시스템 로그, 네트워크, 백업 |
| 악성 입력 | 변조된 저장 파일로 앱을 죽이거나 오동작시키기 |
| 공급망 | 빌드 도구·라이브러리 바꿔치기 |
| 역분석 | APK를 풀어 로직·키 위치 파악 |

## 2. 설계상 보안 원칙

1. **읽기 전용 — 차량 조작 기능 자체가 없다.** `CONTROL_*` 권한을 요청하지 않으며, 제어 API를 호출하는 코드가 없다. 따라서 바통을 통해 차량이 움직이거나 문이 열리는 경로가 구조적으로 존재하지 않는다(심층 방어의 첫 겹).
2. **최소 권한.** 필요한 읽기 권한 7종 + 음성 1종 + 운전석 위치 1종만 쓴다. 인터넷 권한은 라이브러리가 넣더라도 최종 앱에서 제거한다.
3. **오프라인·차량 내부 보관.** 서버로 보내지 않는다. 클라우드 백업·기기 간 이전도 막는다.
4. **최소 수집.** 위치·속도·경로·얼굴·음성·차대번호(VIN)·운전자 이름을 수집·저장하지 않는다. 운전자 신원을 비교하지 않는다.
5. **저장 파일은 신뢰하지 않는다.** 암호화·변조 감지 후에도 내용을 검증한다.

## 3. 적용한 통제 (MASVS 범주별)

| 범주 | 통제 | 구현 위치 | 확인 방법 |
|---|---|---|---|
| STORAGE | 인계 저장 **AES-256-GCM** 암호화, 키는 **Android Keystore**(앱 밖 반출 불가, 하드웨어 지원 시 TEE) | `security/SecureFile.kt` | 에뮬레이터: 파일 앞부분 `BTN1`+무작위 바이트, 평문 단어 0건 |
| STORAGE | 원자적 쓰기(임시 파일→교체): 쓰는 중 전원 차단에도 이전 파일 보존 | `SecureFile.write` | 코드 검토 |
| STORAGE | 예전 평문 파일 자동 이전 후 삭제 | `HandoverStore.load` | 코드 검토 |
| STORAGE | 파일 권한 `rw-------` (앱 본인만) | Android 기본 | `ls -la` 확인 |
| STORAGE | 백업 금지(`allowBackup=false`, `fullBackupContent=false`), Android 12+ 클라우드·기기 간 이전 전부 제외 | `AndroidManifest.xml`, `xml/data_extraction_rules.xml` | 병합 매니페스트 확인 |
| CRYPTO | GCM 인증 태그로 변조 감지 → 변조 시 폐기, IV는 매번 시스템 무작위 | `SecureFile` | E2E-10: 1바이트 변조 → 복원 안 함, 크래시 0 |
| CODE | 저장 형식 입력 검증: 버전·종류·위치 코드·값 범위(0~100)·개수 상한(항목 64, 이력 50)·파일 크기 상한(1MB) | `HandoverCodec`, `SecureFile.MAX_BYTES` | 단위 ST-02~10 |
| CODE | release 코드 축소·난독화(R8) | `build.gradle.kts`, `proguard-rules.pro` | APK 39.7→16.3MB, 실동작 E2E |
| CODE | release에서 로그 완전 차단 (`BatonLog` + R8 규칙 이중) | `security/BatonLog.kt` | release 실행 시 앱 로그 0줄 |
| NETWORK | 인터넷 권한 제거, 평문(HTTP) 금지·사용자 설치 인증서 불신 설정(향후 대비) | 매니페스트, `xml/network_security_config.xml` | 병합 매니페스트에 INTERNET 없음 |
| PLATFORM | 외부 공개 컴포넌트: 실행 화면 1개 + 시스템 전용 수신기 1개(`DUMP` 권한 보호, AndroidX 기본) | 병합 매니페스트 | 확인 |
| PLATFORM | release는 디버그 불가 → `run-as`로 앱 폴더 접근 불가 | 기본 | 확인 ("package not debuggable") |
| RESILIENCE | 서명 키 4096비트 RSA, 저장소 밖 보관, 비밀번호 무작위 32자 | `C:/dev/keys` | — |
| 공급망 | Gradle 배포판 SHA-256 고정, wrapper jar 공식 체크섬 일치 확인, JDK·Gradle 다운로드 시 SHA-256 검증 | `gradle-wrapper.properties` | 확인 |
| 개인정보 | 저장 형식에 위치·이름·VIN 등 필드 없음 | `HandoverCodec` | 단위 ST-11 |

## 4. 점검 중 발견해 고친 것
- 인터넷 권한(불필요), 타이어 권한(사용 불가), 차량정보 권한·VIN 읽기(불필요, 로그 노출 위험) → 제거
- 저장 파일 평문 → 암호화
- 기기 간 이전 경로 열려 있음 → 차단
- release 로그에 차량 상태 기록 → 차단
- R8 적용 시 Pleos SDK 내부 Gson의 제네릭 정보가 지워져 **release에서만** 기능 확인이 전부 실패 → Gson 공식 규칙 추가
- R8이 바통 enum 이름을 바꿔 **release에서만** 저장 형식·SDK 영역 매칭이 깨짐 → enum 이름 유지 규칙

## 5. 남은 위험과 한계 (정직하게)
| 위험 | 현재 | 대응 계획 |
|---|---|---|
| 루팅된 기기에서 Keystore 우회 | 하드웨어 Keystore가 없는 기기에서는 소프트웨어 키 | 실차 하드웨어 보안 모듈 사용 여부 확인 |
| 서명 키 분실·유출 | PC 한 곳에 보관 | 오프라인 백업 2곳 (사용자 작업) |
| 타 앱 화면 덧씌우기(탭재킹) | 바통 화면은 '확인' 정도만 있어 피해 작음 | 필요 시 `filterTouchesWhenObscured` |
| 운영사 모드(서버 연동) 추가 시 | 현재 네트워크 없음 | 추가 시 TLS 고정, 서버 인증, 개인정보 영향평가 |
| 외부 라이브러리 취약점 | AndroidX·Kotlin 최신 안정판, Pleos SDK 내장 Gson 2.10.1(알려진 역직렬화 취약점 CVE-2022-25647은 2.8.9에서 수정) | 제출 전 버전 재확인 |
| 법적 개인정보 해당 여부 | 운전자 프로필과 결합되지 않도록 설계 | 운영사 모드 전 법률 검토 |

## 6. 안전(Safety)과의 경계 — 급발진 등
- 바통은 **차량을 제어하지 않는 읽기 전용 앱**이다. 가속·제동에 개입하지 않으며, 개입해서도 안 된다(서드파티 앱의 구동계 개입은 그 자체가 안전·보안 위험이고 Pleos 앱 심사 원칙에도 어긋난다).
- 급발진 의심 사고의 원인 조사(미국 NHTSA·NASA 2011 토요타 조사: 전자적 원인 미발견, 주원인 페달 오조작·매트·페달 고착 / 국과수 2013~2018 분석: 269건 중 76% 페달 오조작 보도)와 대책(브레이크 오버라이드, EDR, 현대차 PMSA 등)은 **차량 제어기 수준의 순정 기능** 영역이다.
- 바통이 할 수 있는 범위: **제동 계통 이상 신호(브레이크액 부족)를 '안전' 등급으로 다음 운전자에게 출발 전에 넘기는 것**까지. 신호를 지원하는 차량에서만 자동으로 켜진다(에뮬레이터는 미지원 → 숨김). 바통은 "급발진을 막는다"고 주장하지 않는다.
